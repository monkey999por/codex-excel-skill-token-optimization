# 本番リポジトリの初期キャッチアップ用プロンプト

本番リポジトリの調査用コピーをZIPに固め、ChatGPTのチャットにアップロードして深掘りする前提。まず[ChatGPT利用ガイド](chatgpt-zip-usage.md)でZIPの作り方と注意点を確認する。**ChatGPTはZIPを展開して中の全ファイルを自分で一覧・検索・閲覧できる**ので、ファイルを小分けに渡す必要はない。[00. 展開と閲覧範囲の確認](00-access-check.md)で、全件を展開できたかを最初に確かめる。

各ファイルのコードブロックを、ZIPをアップロードした同じチャットへ**一問ずつ**貼り付ける。このリポジトリには本番の skill、script、実データがないため、回答は本番リポジトリの根拠で確認する。01〜22は読み取り専用で、コード実行は展開・一覧・検索・本文表示・件数集計だけに限る。リポジトリのscript・テストの実行、インストール、編集は依頼しない。**01〜22の本文には、README・docsだけで結論を出さず、実装・設定・テストと呼出し経路を深く調べる絶対ルールを入れた。**

**ChatGPTを受け身の要約係にしない。**全ファイルにアクセスできるので、各問でChatGPT自身が必要なファイルを検索して開き、呼出し元・先、設定、テストをたどって問いが解けるまで深掘りする。ユーザーにファイルを求めさせない。根拠は展開したファイルから取った「相対パス:行番号」で示させ、「存在しない」「全て」という主張には検索語・範囲・件数を付けさせる。各回答の冒頭では「今回本文を開いたファイル」と「見つかったが未読の関連ファイル」を示させる。ZIPに含まれない情報（除外した秘密・実データ、履歴、外部システム、運用ルール）は「ZIP外・要確認」として分けさせる。

00で展開を確認し、構成が分からない場合は[00a. 未知のリポジトリを探索](00a-repository-discovery.md)してから、01〜07で目的・入口・構造・処理経路を把握する。次に08〜12で品質と運用の境界を確認し、必要に応じて13〜22を選ぶ。回答を受けたら[追加の問いかけガイド](follow-up-guide.md)に沿って根拠と矛盾を確認する。**一度に全問を投げない**。回答が膨らみ、重要な根拠を追えなくなる。チャットが長くなったら、テーマの区切りで新しいチャットを開いてZIPを再アップロードする。
