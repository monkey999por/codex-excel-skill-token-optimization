# 20. 境界条件と失敗パターン

Microsoft Copilotアプリに次のブロックをそのまま貼り付ける。

```text
【アクセス確認・絶対ルール】このチャットで実際に本文を読める調査用リポジトリのファイル（通常チャットで明示添付した原本、またはCodeタブで開いた許可済みローカルコピー）だけを対象にする。目録やフォルダー名だけでは本文を読めたとみなさない。回答冒頭に読めた相対パスと未確認範囲を示す。必要な原本を開けなければ結論を出さず、追加で必要なファイルを優先順に挙げて止まる。
【調査・絶対ルール】README・docs・コメントの要約だけで結論を出さない。読める範囲の関連SKILL.md、ソースコード、設定、テスト、CIを深く調べ、入口→呼出し元・先→入出力→検証を追い、反例も探す。利用中のMicrosoft Copilotアプリにない検索・閲覧・実行機能を使ったふりはしない。
【根拠ルール】実装に関する結論は相対パスと確認できた行番号で裏付ける。行番号が見えない場合は相対パス＋関数名・見出し＋短い非機密の根拠を示し、行番号を作らない。文書だけの事項は「文書上の記述」、実装未確認の事項は「推測・未確認」と明記する。後述の「ファイル:行」指定もこのルールに従う。
このリポジトリを読み取り専用で調査してください。編集・スクリプト実行・本番データの閲覧はしないでください。
入力なし、空シート、列の不足・追加、重複ID、巨大ファイル、壊れたExcel、部分的なAI出力、JSON形式違反、個別チェック失敗、集計途中の中断、前回成果物の混入について、現在の実装がどう振る舞うかを整理してください。
実際にテストされているケース、コードから挙動を読めるだけのケース、未対応・不明なケースを分けてください。例外を握りつぶす箇所と、失敗後に部分ファイルが残る箇所を優先して示し、根拠のファイル:行を付けてください。
```
