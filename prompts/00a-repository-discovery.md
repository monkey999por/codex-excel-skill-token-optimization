# 00a. 構成が不明なリポジトリから始める

先に[00. 展開と閲覧範囲の確認](00-access-check.md)を実施する。関連ファイルのパスを事前に知る必要はない。ChatGPTはZIP内の全ファイルを自分で検索できるので、**ユーザーが目録や原本を小分けに渡す必要はない**。ChatGPT自身に**全体目録 → 入口候補 → 本文の呼出し追跡**の順で探索させる。

ただし「全ファイルを見られる」ことと「全ファイルを読んで理解した」ことは別。ChatGPTが一度に考慮できる量には限りがあるため、検索で範囲を絞りながら、結論に使うファイルは本文を開かせる。

## 最初のプロンプト

```text
アップロードしたZIPは本番リポジトリの調査用コピーで、私はまだ構成を知りません。展開済みのディレクトリを使い、あなた自身が探索を主導してください。ユーザーにファイルを求める必要はありません。
【絶対ルール】コード実行は展開・一覧・検索・本文表示（行番号付き）・件数集計だけに使い、リポジトリのscript・テストの実行、インストール、ネットワーク接続、編集はしない。README・docsの説明だけで結論を出さない。結論に使うファイルは本文を開き、相対パス:実際の行番号で示す。秘密値や実データ本文は表示しない。
1. ディレクトリツリー（深さ3程度、依存ライブラリ・生成物は件数だけ）と拡張子別件数から、skills、scripts、設定、参照資料、テスト、CI、入力例、生成物の置き場所の候補を挙げてください。
2. SKILL.md、実行入口（CLI・main・__main__・ジョブ定義・Makefile等）、CI設定を検索して全件列挙し、入口候補を重要度順に最大5件選んでください。
3. 上位の入口候補それぞれについて本文を開き、呼び出すscript・参照ファイル・設定キーを特定し、そのファイルも開いて一段ずつ追ってください。ファイル名リテラルや関数名を横断検索して、呼出し元や他の参照箇所も確認してください。
4. 入口ごとに「入口 → 主な呼出し先 → 入出力ファイル → 対応するテスト」を相対パス:行で示してください。
5. 本文を開いたファイル数と、関連しそうだが未読のファイル（理由付き）を分けてください。リポジトリ全体を網羅したとは言わず、次に深掘りすべき論点を優先順に3件提案してください。
```

**探索の停止条件**：主要な入口ごとに、呼出し先・入出力・テストが根拠付きでつながったら、01以降の個別テーマへ進む。重要な呼出し先が「ZIP外」（外部パッケージ、除外したファイル、別リポジトリ）なら、その名前と参照箇所を記録して結論を保留する。
