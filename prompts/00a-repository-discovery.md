# 00a. 構成が不明なリポジトリから始める

先に[00. 本文アクセス確認](00-access-check.md)を実施する。関連ファイルのパスを事前に知る必要はない。調査用コピーから、**機械的な全体目録 → 入口候補 → 本文の呼出し追跡**の順に探索する。目録だけでは内容の妥当性や関連性は確定しない。

## 最初の目録

リポジトリをローカルに閲覧できる場合、許可済みの調査用コピーのルートでファイル一覧を表示する例：

```bash
rg --files --hidden -g '!.git' -g '!node_modules' -g '!vendor' -g '!.venv' -g '!dist' -g '!build'
```

この例は**ターミナルに一覧を表示するだけ**。実リポジトリに応じて除外対象を調整し、Copilotへ渡す前にパス名自体に秘密情報がないか確認する。`rg`はignore設定によって一部ファイルを表示しないため、これは完全性の証明にはならない。件数・拡張子別件数・第一階層の構成も機械的に確認する。実データや秘密値の本文を目録に含めない。

OneDrive上のものをローカルスクリプトで調べる場合は、同期済みフォルダーを列挙するか、管理者が許可した[Microsoft Graphのファイル列挙](https://learn.microsoft.com/en-us/graph/api/driveitem-list-children?view=graph-rest-1.0)を使う。Graphから各ファイルの[`webUrl`](https://learn.microsoft.com/en-us/graph/api/resources/driveitem?view=graph-rest-1.0)を得られるが、URL一覧は索引にすぎない。**URLをCopilotへ渡しても、本文の自動取得・フォルダー全件の読解を保証しない。**

## Copilotアプリの探索機能で分岐する

- **Codeタブが使える**：許可済みの隔離ローカルコピーを開き、下のプロンプトを送る。Copilot Codeはローカルフォルダーや[接続済みGitHubリポジトリへの質問](https://learn.microsoft.com/en-us/copilot/code/code-github)をサポートするが、[プレビュー機能](https://learn.microsoft.com/en-us/copilot/code/get-started)であり、利用可能とは限らない。開いたフォルダーに書込み権限があるため原本を渡さない。
- **通常チャットのみ**：目録と少数の原本を添付し、まず入口候補を特定する。回答が参照する呼出し先を次の回で追加する。[Copilot Chatのフォルダー添付](https://support.microsoft.com/en-us/microsoft-365-copilot/refer-to-specific-files-and-more-in-microsoft-365-copilot?preview=true)が画面上で使える場合も、異なる階層の数ファイルの本文を読めるか検査し、全件を読めたと推定しない。
- **OneDrive内のCopilotのみ**：[フォルダーQ&A非対応・最大5ファイル](https://support.microsoft.com/en-us/onedrive/frequently-asked-questions-about-copilot-in-onedrive)なので、全体探索の主体にはしない。

### Codeタブ向けの最初のプロンプト

```text
これは許可済みの調査用コピーです。まだ構成を知りません。編集・コマンド実行・ネットワーク接続をせず、実際に閲覧できる範囲でリポジトリを探索してください。
最初に第一階層とファイル種別を棚卸しし、SKILL.md、実行入口、script、設定、テスト、CIの候補を探してください。READMEやdocsの説明だけで結論を出さず、候補ごとに本文を開いて存在を検証してください。
入口候補を3件以内に絞り、各候補について、原本相対パス、本文で確認した見出し・関数名・設定キー、呼出し先候補、まだ開いていない関連ファイルを示してください。
読めた件数と未確認件数を分け、全体を網羅したとは言わないでください。あなたが次に読むディレクトリやファイルを理由・確認点付きで優先順に選び、自分で読めるものは追跡を続けてください。アクセスできないものは具体的な相対パスをユーザーに要求してください。
```

### 通常チャット向けの最初のプロンプト

```text
添付した目録は候補の索引であり、内容の証拠ではありません。まず目録から、調査対象として優先すべきSKILL.md、実行入口、script、設定、テストの候補を挙げてください。
今回添付した原本についてだけ本文を確認し、相対パスと実在する見出し・関数名・設定キーを示してください。未添付のファイルを読んだふりをせず、あなた自身が次に必要なディレクトリ一覧や原本を選んで、具体的な相対パス（不明なら必要な階層）・優先順・理由・確認点とともに最大5件要求してください。受け取った後は本文から呼出し先・設定・テストを追い、必要なら次の対象をさらに要求してください。
READMEやdocsだけでアーキテクチャを断定しないでください。
```

**探索の停止条件**：目録にある入口候補と関連テスト・設定について、読めたもの／読めないものを突き合わせ、重要な呼出し経路に未確認箇所が残る場合は結論を保留する。
