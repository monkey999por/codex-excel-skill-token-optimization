# Copilot の回答を受けた後の追加の問いかけ

最初の回答を完成した設計書として扱わず、**主張 → 根拠 → 反例 → 未確認事項**の順に確認する。基本的には一度に一つの論点を深掘りする。以下は本番リポジトリの調査用コピーを閲覧できるMicrosoft Copilotアプリへ送る追加質問のテンプレート。`[ ]` 内を実際の回答に合わせて置き換える。どの質問でも読み取り専用とし、本番データや秘密値を回答に出させない。

## 回答の状態に応じた次の一問

| 回答の状態 | 次に聞くこと | 合格の目安 |
|---|---|---|
| 根拠がない・抽象的 | その主張の根拠を再提示 | ファイル:行と具体的なコード・設定が付く |
| 根拠が文書だけ | 実装側の対応箇所を確認 | 文書とコードの一致／不一致が分かる |
| 「存在しない」と断定 | 探索した範囲を確認 | 検索対象が明示されるか、断定を撤回する |
| 二つの回答が矛盾 | 同じ入力・版・経路かを突合 | 条件差、版差、誤読のどれかが分かる |
| 一般論や推測が混じる | 事実と推論を分離 | 推論にラベルが付く |
| 処理フローが飛んでいる | 直前・直後の呼出しを追跡 | 入力と出力を結ぶ経路が埋まる |
| テストの存在だけで「安全」とする | テスト対象と未検証範囲を確認 | 品質を保証しない条件が分かる |
| 「不明」が残る | リポジトリ内か運用外か分類 | 次に読むファイルか確認すべき担当が決まる |

## そのまま使える追加質問

### A. 根拠の再確認

```text
【アクセス確認・絶対ルール】このチャットで本文を読める調査用リポジトリの原本だけを調べてください（通常チャットでは明示添付ファイル、Codeタブでは許可済みローカルコピー）。目録やフォルダー名だけでは本文を読めたとみなさず、必要な原本を読めないなら結論を保留して追加ファイルを依頼してください。読めた相対パスと未確認範囲を先に示してください。
【調査・根拠ルール】README・docsだけで結論を出さず、関連SKILL.md・ソースコード・設定・テストの呼出し元/先、入出力、検証を追ってください。実装の根拠は相対パス:行、行番号が見えなければパス＋関数名等で示し、番号を捏造しないでください。
【主体的な追加要求・絶対ルール】あなたが次に見るべきディレクトリ一覧・原本ファイルを選び、本文を読めない場合は具体的な相対パス（不明なら必要な階層）・理由・確認点を優先順に最大5件要求してください。受け取ったら本文から関連する呼出し元・先、設定、テストを追い、必要なら次の対象をさらに要求してください。重要な未確認箇所を残したまま結論を確定しないでください。
読み取り専用で確認してください。先ほどの「[主張]」について、根拠となるファイル:行と、その行が主張をどう支えるかを示してください。直接の根拠がない場合は「推測」に修正し、必要な確認先を挙げてください。編集・実行・本番データの表示はしないでください。
```

## 質問を打ち切る条件

対象の入口・処理経路・入出力・検証・失敗時の扱いが根拠付きで説明できれば、その論点は一旦完了。さらに深掘りするのは、(1) 回答が矛盾する、(2) 本番事象に直結する境界が不明、(3) 変更判断に必要な受入条件が不明、のいずれかの場合。根拠がリポジトリに存在しないなら Copilot への同じ質問を繰り返さず、運用資料・担当者・実行ログへ確認先を切り替える。
