# 18. 機密情報・権限・データ境界

Copilot 等に次のブロックをそのまま貼り付ける。

```text
【アクセス確認・絶対ルール】このチャットで実際に本文を読めるOneDrive添付・参照ファイルだけを対象にする。ZIP名やフォルダー名が見えても内部を読めたとみなさない。回答冒頭に読めた相対パスと未確認範囲を示す。必要なZIP内ファイルを開けなければ結論を出さず、解凍・添付してほしいファイルを優先順に挙げて止まる。
【調査・絶対ルール】README・docs・コメントの要約だけで結論を出さない。読める範囲の関連SKILL.md、ソースコード、設定、テスト、CIを深く調べ、入口→呼出し元・先→入出力→検証を追い、反例も探す。Copilotにない検索・解凍・実行機能を使ったふりはしない。
【根拠ルール】実装に関する結論は相対パスと確認できた行番号で裏付ける。行番号が見えない場合は相対パス＋関数名・見出し＋短い非機密の根拠を示し、行番号を作らない。文書だけの事項は「文書上の記述」、実装未確認の事項は「推測・未確認」と明記する。後述の「ファイル:行」指定もこのルールに従う。
このリポジトリを読み取り専用で調査してください。編集・スクリプト実行・本番データの閲覧はしないでください。秘密値や実データ本文を回答に転載しないでください。
仕様書・中間ファイル・ログ・AI入力・最終成果物に機密情報が流れる可能性を、コードと設定から分かる範囲で追ってください。保存先、削除・保持の設定、外部送信の有無、アクセス権、マスキング、誤公開防止を確認してください。
実装で確認できる対策と、運用担当へ確認すべきポリシーを分けてください。各項目に根拠のファイル:行を付け、秘密値は表示しないでください。
```
