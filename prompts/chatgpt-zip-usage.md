# ChatGPTにZIPを渡して本番リポジトリを調べる方法

ここでいうChatGPTは、ファイルのアップロードとコード実行（Pythonによるデータ分析機能）が使えるChatGPTのチャットを指す。本番リポジトリはこの資料のリポジトリとは別物で、こちらから実物を検証できていない。プラン、ワークスペースの管理者設定、利用規程によって可否・上限が変わるので、使う前に自分の環境と社内ルールで確認する。

## ポイント：ZIPの中身をChatGPTがすべて見られる

ChatGPTはアップロードされたZIPをコード実行環境で展開し、**中の全ファイルを自分で一覧・検索・閲覧できる**。そのため次の運用が前提になる。

- **ファイルを小分けに渡さない。** ZIPを1つ渡せば、必要な原本はChatGPTが自分で探して開く。ユーザーに「このファイルを添付してください」と求めさせない。
- **調査をChatGPTに主導させる。** 入口を見つけ、呼出し先・参照ファイル・テストを検索してたどり、問いが解けるまで自走で深掘りさせる。
- **網羅性を検索で示させる。** 「存在しない」「全て」という主張には、検索語・対象範囲・ヒット件数を付けさせる。全ファイルにアクセスできるので、これを要求できる。
- **行番号を実物から取らせる。** 展開したファイルを行番号付きで表示できるので、根拠は「相対パス:行番号」で求める。

一方で、**見られることと読んで理解したことは別**。ChatGPTが一度に考慮できる量には限りがあり、全ファイルを常に頭に入れているわけではない。結論に使うファイルは毎回本文を開かせ、記憶や要約だけで答えさせない。

## ZIPの作り方

1. 社内規程上、ChatGPTへの入力が許された環境（例：組織が契約したワークスペース）かを確認する。
2. 調査用コピーからZIPを作る。追跡済みファイルだけを固める `git archive` が簡単で、`.git`・未追跡ファイル・ローカルの生成物が入らない。

   ```bash
   # リポジトリのルートで実行。出力先はリポジトリの外にする
   git archive --format=zip -o ../repo-investigation.zip HEAD
   ```

3. **機密の除外を人が確認する。** 追跡済みでも `.env`、鍵、認証情報、顧客データ、実データExcel、ログが含まれることがある。

   ```bash
   unzip -Z1 ../repo-investigation.zip | grep -Ei '(^|/)\.env|secret|credential|token|\.pem$|\.key$|\.p12$|\.xlsx?$|\.csv$|\.log$'
   # 除外する場合
   zip -d ../repo-investigation.zip 'path/to/file'
   ```

   ヒットしたものは中身を見て判断する。テスト用の架空Excelなど、調査に必要で機密でないものは残してよい。逆に、パス名に出ない機密（設定ファイル内の埋込み値など）もあり得るので、grepだけで安全とはみなさない。

4. 依存ライブラリ（`node_modules`、`.venv`、`vendor`）や大きな生成物が入っていれば除外する。件数とサイズが膨らみ、検索のノイズになる。

### 履歴を含めたい場合

ZIPに `.git` は入らないため、[16. 変更履歴と設計判断](16-history-and-decisions.md)や[21. 所有者](21-ownership-and-support.md)で履歴を使いたい場合は、テキストで書き出して同梱する。

```bash
mkdir -p _meta
git log --date=short --stat -n 500 > _meta/git-log.txt
zip ../repo-investigation.zip _meta/git-log.txt
rm -r _meta
```

コミットメッセージや作者名に個人情報・機密が含まれる場合は、同梱しないか必要な範囲に絞る。

## 進め方

1. 新しいチャットでZIPをアップロードし、[00. 展開と閲覧範囲の確認](00-access-check.md)を送る。件数の一致と、実在する行番号付きの本文表示を確認する。
2. 構成が分からなければ[00a. 未知のリポジトリを探索](00a-repository-discovery.md)を送る。
3. [索引](README.md)の01〜22を**一問ずつ**送る。各プロンプトに「ZIPから自分で探して開く」「呼出し先を追い続ける」「根拠は相対パス:行」のルールを入れてある。
4. 回答を受けたら[追加の問いかけガイド](follow-up-guide.md)で根拠・矛盾・未確認事項を詰める。

## 注意点

- **コード実行の範囲を絞る。** プロンプトでは展開・一覧・検索・本文表示・件数集計だけを許可し、リポジトリのscript・テストの実行、インストール、編集を禁止している。実行環境には本番の依存・設定・データがなく、実行結果は本番の挙動を示さないため。
- **セッション切れに注意。** しばらく操作しないと、展開済みファイルが実行環境から消えることがある。ChatGPTが「ファイルが見つからない」と言ったら同じZIPを再アップロードする。記憶で答え続けていないかを確認する。
- **長いチャットは分ける。** 会話が長くなると前半の内容が考慮されにくくなる。テーマの区切り（例：01〜07、08〜12）で新しいチャットを開き、ZIPを再アップロードする。前のチャットの結論は、要約ではなく「確認済み事実と根拠の相対パス:行」の形で引き継ぎ、新しいチャットで本文を開き直させる。
- **ZIPの版を固定する。** 調査の途中でZIPを作り直すと、回答間で版がずれる。ZIP名に日付やコミットIDを入れ、作り直したら以前の結論を再確認する。
- **アップロード上限はプラン・時期で変わる。** 大きすぎて受け付けられない場合は、依存ライブラリ・生成物・大きなバイナリを除外して作り直す。

## 失敗を見分ける基準

- 「展開しました」とだけ言い、件数やツリーの出力を示さない → 実行を伴っていない可能性。出力を示させる。
- 相対パスは挙げるが、本文の関数名・設定キー・行番号を示せない → その本文を開いていない。開かせる。
- 「存在しない」と断定するが、検索語・範囲・件数がない → 検索させ直す。
- 前の回答と同じ主張を、本文を開かずに繰り返す → 記憶に頼っている。該当ファイルを開き直させる。
- ZIP外の情報（本番の設定値、運用ルール、外部システム）を断定する → 「ZIP外・要確認」に分けさせる。

ChatGPTの回答は本番実装の保証ではなく、根拠確認付きのキャッチアップ資料として扱う。重要な主張は、示された相対パス:行を人が開いて確認する。
